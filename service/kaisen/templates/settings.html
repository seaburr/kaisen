An existing repository; it can be empty. Kaisen writes to its own branch and never touches your default branch unless you name it below.

How to create the access token (about 2 minutes)
  1. Open GitHub > Settings > Developer settings > Fine-grained tokens > Generate new token.
  2. Token name: kaisen. Expiration: 90 days (you can paste a new one here any time).
  3. Resource owner: the account or organization that owns the repository above.
  4. Repository access: Only select repositories, then pick just that one repository.
  5. Repository permissions: set Contents to Read and write and Pull requests to Read and write. Metadata: Read-only is added automatically. Leave everything else at No access.
  6. Press Generate token, copy it (it starts with github_pat_) and paste it above. GitHub shows it only once.
  7. If the repository belongs to an organization, an owner may need to approve the token under the organization's Personal access tokens settings.
  8. Save, then press Test GitHub below.

Why only these permissions: Kaisen only needs to create commits and branches and open a pull request. Without Workflows or Administration permission it cannot change your Actions, settings or other repositories. The token is stored encrypted and never shown again.

PicoPaaS (live previews)

Kaisen deploys each project as a live preview app named kaisen-<project> in your PicoPaaS account (or in the project below). Previews are optional.

How to set this up
  1. In PicoPaaS, open Account > API keys, create a key with full access and paste it below.
  2. New accounts can run 1 app, and Kaisen itself uses it. Pick a project below that has free slots, or ask your admin to raise your limit.
  3. Save, then press Test PicoPaaS.

Previews download their files from this address, so it must be reachable from PicoPaaS. Filled in automatically from your browser address; change it if that is wrong.
